# 単一 CDF から始める実験計画

目的は，一条件で学習経路と数値精度を検証し，点数・最適化・モデル容量の探索範囲を狭めることです．
一条件の結果を，全波長・全入射方向に最適な設定，条件間補間の精度，レンダリング速度とは扱いません．
現在のモデル・座標・保存形式は [単一条件の仕様](RAINBOW_SINGLE_CONDITION.md) を参照してください．

## 1．固定する教師と比較のルール

**非球形雨滴・斜入射で，出射方位角にも構造がある一つの CDF** を代表例に選びます．
球形や厳密な軸入射は簡単な回帰検証には適していますが，二次元の円周 coupling の探索には不十分です．
波長・入射方向・粒子形状とサイズ，元の CDF ファイル，外部 `hg.g` を固定します．
ここで変える点数は学習 pool の点数であり，教師 CDF の解像度ではありません．
前方ピークの切除，教師の平滑化，ゼロ密度への floor，CDF の対称化は行いません．

- `training.data_seed=2026` を固定し，独立 stream の validation 32,768 点と test 65,536 点を共通にします．
- `training.seed` は初期値・minibatch 用です．候補比較は同じ値で開始し，上位候補を少なくとも 3 seed で再試行します．
- 現実装の学習点生成は，同じ `data_seed` で大きな pool の先頭が小さな pool と一致することを検査しています．
  別のサンプラでも同じ seed だけでこの入れ子関係が成立するとは仮定しません．点群 hash と実装を記録します．
- 初期値だけの反復と，学習 pool の生成まで変える反復は別実験です．後者には別の `data_seed` と共通の外部評価点を使います．
- モデル選択には validation を使います．最終 test は設定・重みを選んだ後の報告用です．
  現 CLI は各完了 run の test を自動保存しますが，探索中の順位付け・打切りにはその値を参照しません．
- 各 run の設定，入力 hash，精度，環境，seed，更新数，処理点数，所要時間と重み容量を保存します．

## 2．まず精度と学習経路を検証する

v0.4 の出発点は MLP の重み・HG・方向・RQS を FP32 とし，教師 CDF と評価統計を FP64 に保ちます．
`precision-rainbow` は，同じ学習済み重み・教師点・基底乱数で FP32，FP64 参照，FP16 に丸めた重みを比較します．
これは演算精度の比較です．FP32 と FP64 で別々に学習した結果の比較は，最適化への影響を調べる別実験です．

1. 恒等残差が外部 HG と一致すること，CDF の sample/PDF と座標が一致することを確認します．
2. RQS の順逆変換，正規化，周期 seam，鏡映，軸入射，極付近を検査します．
3. 固定重みで log PDF の差，生成方向の差，sample 時と再評価時の log PDF の差を調べます．
   平均だけでなく裾と最大誤差，非有限値を確認し，近似誤差と数値誤差の許容範囲を分けて決めます．
4. 同一設定・同一 split の学習を開始し，HG より validation KL が改善するかを確認します．
5. 最良重みを FP16 に丸め，KL の増加と sample/PDF の整合性を再確認します．必要なら量子化を考慮した学習を検討します．

FP16 に丸めた重みを FP32 演算で評価する検査は，**重みの保存精度による誤差の診断**です．
OptiX CoopVec 内の活性化・積和・丸めを再現した検証ではありません．最終段階では実際の CoopVec と比較し，
レンダラの `sample` と `pdf_eval` が同じ重み・評価方式を使うことを確認します．
CPU テストの成功や CUDA テストの skip は，CUDA 学習・CoopVec の検証結果には含めません．

## 3．一度に全組合せを探索しない

以下は初期探索用の候補であり，論文の推奨値や実データで確認した最適値ではありません．
基準は `L=4`，`K=16`，隠れ層 `[64,64]`，`N=65536`，`B=1024`，`T=2000`，Adam の `lr=1e-3` です．
`L` は scalar coupling 層数，`K` は区間／全円周の bin 数です．鏡映有効時の円周の独立 bin 数は `K/2` です．

| 段階 | 変える候補 | その段階で調べること |
|---|---|---|
| A：学習率 | `3e-4, 1e-3, 3e-3` | 発散せず，validation が改善する学習率帯 |
| B：学習点数 | `4096, 16384, 65536, 262144` | pool 増加による改善と飽和，train/validation の差 |
| C：モデル容量 | `L=2,4,8`；`K=8,16,32`；隠れ層 `[32,32],[64,64],[128,128]` | 学習不足と容量不足を分け，精度・容量・速度の妥協点を得る |
| D：batch と更新量 | `B=512,1024,4096`；`T=2000` から曲線に応じて調整 | 実 GPU での効率と収束，batch と学習率の相互作用 |
| E：確認実験 | 上位候補の複数 seed，鏡映あり／なし，FP16 重み丸め | 改善が反復のばらつきや数値誤差より大きいか |

C ではまず一要因ずつ基準から変え，有望な少数の組合せだけを追加します．
容量を増やすと必要な点数も変わるので，上位候補では B の結果を再確認します．
batch を変えた場合も学習率を少数候補で再確認します．bin 幅・高さ・slope の下限は最初は固定します．
これらの下限も表現可能な集中度を制限するため，後から変える場合は明示的な ablation とします．

固定 pool から復元抽出するので，ここでの基本予算は更新数 `T` と処理点数 `T*B` です．
平均的な点の再利用回数は `T*B/N` で，基準設定では 31.25 です．これは全点を一巡する通常の epoch 数ではありません．
N の比較ではまず T と B を固定しますが，大きな N の曲線がまだ改善中なら，点数の効果がないとは結論しません．
共通予算での比較と，十分収束させた比較を分け，更新数・処理点数・実時間の軸を記録します．

`steps` を変更した checkpoint の再開は，同じ実験の厳密な続行ではありません．
延長の可能性がある場合は，例えば最初から `steps=4000` とし，`--max-steps-this-run 2000` で一時停止して，
同じ設定の `checkpoint.pt` から残りを再開します．2,000 更新完了を予定した run とは区別します．

## 4．loss と評価値をどう読むか

学習は教師分布 p から生成した点に対する NLL です．密度は立体角 `sr^-1` に関して評価します．

$$
L=-\mathbb E_p[\log q(\omega)],\qquad
D_{\rm KL}(p\|q)=\mathbb E_p[\log p(\omega)-\log q(\omega)].
$$

連続密度は 1 を超えられるため，**NLL が負でも正常**です．同じ教師・同じ測度なら NLL と forward KL の順位は一致します．
点には教師 PDF や `sin(theta)` を重ねて掛けません．角度画像の各画素を等重みにした誤差は立体角積分とは異なります．
異なる条件では教師のエントロピーが変わるため，NLL の絶対値だけで近似の良否を比べず，KL も報告します．

独立な n 点で `z_i=log p(omega_i)-log q(omega_i)` とすると，KL 推定値はその平均，Monte Carlo 標準誤差は
`sample_std(z)/sqrt(n)` です．有限サンプルの KL 推定値が僅かに負になることはあり，0 に置換しません．
同じ評価点で二モデルを比べる場合は `log q_B-log q_A` の平均と標準誤差を使うと，差を直接評価できます．
選択に使った validation の誤差棒は，候補探索による選択バイアスまで補正するものではありません．
評価点の Monte Carlo 誤差と，学習 seed 間のばらつきは別々に報告します．

proposal の品質には NF から実際に生成した M 点と，その NF の PDF を用います．

$$
w_i=\frac{p(\omega_i)}{q(\omega_i)},\quad \omega_i\sim q,\qquad
{\rm rESS}=\frac{(\sum_i w_i)^2}{M\sum_i w_i^2}.
$$

rESS は 1 に近いほど重みが均等ですが，稀な大きい重みを取り逃がすと楽観的になります．
複数の proposal stream や点数増加で安定性を確認し，重みの平均・裾も調べます．
これは位相関数 p を積分する proposal の診断であり，照明・可視性・MIS を含む実際の画像分散の保証ではありません．

[Rezende et al. (2020), §4](https://proceedings.mlr.press/v119/rezende20a/rezende20a.pdf) の主要実験は
reverse KL `D_KL(q||p)` による学習と ESS による評価です．本プロジェクトの sample-based MLE は forward KL に対応します．
方向の異なる KL を同じ数値指標として比較しません．同論文の補足 Appendix J は点群からの学習も扱います．
一般的な MLE と forward KL の関係は [Papamakarios et al. (2021), §2.3.1](https://jmlr.org/papers/v22/19-1028.html) も参照してください．

## 5．既存の図と学習中の監視

`plots/` の教師 PDF，CDF 点群，NF PDF は，同じソルバ座標・アスペクト比に揃え，二つの PDF で対数色尺度を共有します．
点群マップの見かけの密集度には角度座標の面積要素が影響するため，色の明るさと直接同一視しません．
定量評価に加えて，ピークの位置，方位角の回転・鏡映，前方／後方の取り違えを確認します．

TensorBoard と `history.jsonl` では minibatch NLL，固定 training subset の NLL，validation NLL/KL，
勾配 norm，学習率，更新数を確認します．`monitoring.jsonl` の時間・処理速度も併用します．
`plot-history` は保存履歴から学習曲線を再生成します．起動方法は [README](../README.md) を参照してください．

| 曲線の傾向 | 次に確認すること |
|---|---|
| train と validation がともに改善中 | まず更新予算；容量不足と早合点しない |
| train は改善し，validation が悪化 | pool の不足や過学習；点数・容量・最良 checkpoint を比較 |
| 両方が早期に停滞 | 学習率と勾配，HG 初期値，その後に容量 |
| loss／勾配が急増，非有限値が出る | 精度診断と学習率；教師を改変して問題を隠さない |

minibatch の揺らぎと固定集合の曲線を区別し，図の見た目だけで候補を選びません．

## 6．鏡映の根拠と，本プロジェクトで追加した構成

鏡映を三つに分けます．(a) 雨滴・入射状態の物理的対称性，(b) equivariant flow の既存の一般原理，
(c) それを実現する本プロジェクトの RQS パラメータ共有です．(c) を原論文そのままの方式とは呼びません．
今回の具体的構成の新規性を文献調査で確立した，という主張も行いません．

[Sadeghi et al. (2012), §3.4・式 (1)](https://doi.org/10.1145/2077341.2077344) の雨滴形状を回転体として使う場合，
粒子軸と入射方向を含む面で鏡映しても形状と入射方向は同じです．均質・等方的な水，非偏光入射，
偏光を合算したスカラー密度という条件では，この幾何学的対称性から二方向の散乱強度の一致が導かれます．
NF の局所 `+z` を入射伝播方向，`+x` を粒子軸の入射方向に垂直な成分に合わせると，

$$
R(x,y,z)=(x,-y,z),\qquad q(x,y,z)=q(x,-y,z).
$$

z は保存されるので前方と後方を同一視しません．雨滴の上下対称性も仮定せず，入射条件の符号を保持します．
正準ソルバ座標では `eta=sin(alpha)`，`phi=wrap(phi_s-pi/2)` なので，鏡映は
`phi_s -> wrap(pi-phi_s)` です．元の表の `phi_s -> -phi_s` とは異なります．記録されたフレームで比較します．

[Köhler et al. (2020), Theorem 1](https://proceedings.mlr.press/v119/kohler20a/kohler20a.pdf) は，
不変な基底分布を equivariant な写像で変換すると密度の対称性が保たれる一般原理を示しています．
本モデルは HG 座標 `t=H_g(mu)`，全周座標 `v=(phi+pi)/(2*pi)` でこの原理を用います．
鏡映は `(t,v)->(t,1-v)` です．t 側の conditioner は偶関数 `cos(phi)` を使い，
v 側の RQS は半周の幅・高さ・knot slope をもう半周に反転共有して `F(1-v)=1-F(v)` を満たします．
各層とその合成が鏡映と交換可能なので，HG の鏡映対称性を維持できます．
全周の確率変数を保持しており，絶対値に折り畳んだ点に別の乱数で符号を戻す方式ではありません．

円周・区間 RQS は Rezende et al. の構成に基づきますが，HG 座標と上記の鏡映共有は明示的な拡張です．
有限な極密度は球面全体で滑らかな写像・連続密度を保証しません（同論文の補足 Appendix A.1）．
また，軸入射の方位角一様性を実現する `A=sqrt(1-eta^2)` の gate も本プロジェクトの設計です．
非軸入射で spline と恒等写像を A で凸結合する形は物理から一意に決まらず，表現族を制限します．
この仕様は保持して評価し，変更するなら独立したモデル比較として記録します．

教師 CDF は対称化していません．保存分布に数値的な非対称性があれば対称モデルの誤差に含まれます．
`mirror_symmetry=false` との比較を行い，形状・偏光条件が変わる場合には対称性の前提を確認し直します．

## 7．条件付き学習と Optuna に進む時点

一条件では条件入力が定数になるため，波長・入射角のエンコード方法，条件間補間，条件付き g の供給方法は選べません．
単一条件で絞った数候補を，難しさの異なる 3～5 条件で確認した後，条件方向に分割した validation を設けます．
その段階で標準化，one-blob，Fourier などのエンコードと conditioner 容量を比較します．

Optuna は曲線と妥当な予算が分かった段階で導入します．最初は N・batch・更新予算を固定し，
validation NLL を目的値に，学習率・L・K・隠れ層の小さな候補集合を TPE で 20～30 trial 程度調べる案です．
この trial 数も経験的な開始案です．早い段階で遅い候補を切り過ぎないよう，pruning の warmup は実測曲線から決めます．
上位候補は同じ予算・複数 seed で再評価し，最終 test は目的値に使いません．
[Optuna の sampler／pruner の公式解説](https://optuna.readthedocs.io/en/stable/tutorial/10_key_features/003_efficient_optimization_algorithms.html) を参照してください．
本リポジトリに Optuna の自動探索ループが実装済みである，という意味ではありません．
