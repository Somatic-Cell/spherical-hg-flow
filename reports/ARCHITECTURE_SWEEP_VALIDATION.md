## 全体の検証結果

最新 checkout の `src` を `PYTHONPATH` に指定して，全テストを実行しました．

```text
pytest -q
398 passed, 17 skipped in 116.21s (0:01:56)

ruff check .
All checks passed!
```

17 件の skip は CUDA を必要とする 9 件と，実際の Windows CMD を必要とする 8 件です．
成功件数へ含めていません．Windows BAT については，移植可能な静的テストが成功しています．

新しい architecture sweep の対象テストは 13 件が成功しました．実際の小規模な子プロセス学習で，
次を確認しました．

- 異なる L と hidden features が checkpoint のモデル構成とパラメータ数へ反映される．
- 異なる学習率を独立した候補として実行し，共通の固定学習・検証点群を使う．
- milestone と点群の識別情報を保持し，固定学習 pool の全点を可視化する．
- 完了候補の再実行と report-only は，新たな最適化を行わない．
- 未完了候補の checkpoint 再開後に，連続学習の model，optimizer，RNG，履歴と一致する．
- 入力・保存結果の改変を集計更新前に拒否する．
- 失敗候補を残して次候補へ進み，全候補の完了前には最終選択を作らない．
- validation と test の順位を逆にしたテストでも，選択に validation を使う．
- 異なる checkout の import と，同じ出力先への同時実行を拒否する．

## 配布する全 10 構成の短い実行

テスト群とは別に，専用 CLI から配布予定と同じ全 L / hidden features / LR と K=64 を実行しました．
計算機構を確認するため，CPU を明示指定し，合成教師，N=128，batch size=32，
4 更新，milestones=2/4 としました．これは利用者の Rainbow CDF の学習結果ではありません．

| L | hidden features | 学習率 | 各モデルのパラメータ数 | 完了試行数 |
|---:|---|---|---:|---:|
| 4 | `[64,64]` | 0.001，0.003 | 54,852 | 2 |
| 4 | `[128,128]` | 0.001，0.003 | 141,892 | 2 |
| 8 | `[64,64]` | 0.001，0.003 | 109,704 | 2 |
| 8 | `[128,128]` | 0.001，0.003 | 283,784 | 2 |
| 16 | `[64,64]` | 0.001，0.003 | 219,408 | 2 |

10 試行すべてが 4 更新に到達し，全体の status は `complete` でした．
各 milestone の比較図と角度診断図は，それぞれ 20 組生成されました．
全体の `summary.png` は実際に開き，ラベル，数値軸，注記が読めることを確認しました．

さらに，配布用 JSON の N=262,144 / 20,000 更新 / 10 構成を変更せず，CPU を明示指定した
`--dry-run` を合成教師で実行しました．`status=ready`，`trial_count=10` となり，
新しい実験出力ディレクトリを作らず終了しました．これは本番回数の学習を実行したという意味ではありません．

CUDA 指定のまま同じ検証を行うと，利用不可のエラーと終了コード 1 になり，
実験出力ディレクトリは作成されませんでした．CPU fallback が自動ではないことを確認しています．

## 検証の限界

利用者の実 CDF，RTX 3070，CUDA 13.0，Windows CMD での新しい 10 試行は，こちらでは実行していません．
夜間実行の所要時間と大きいモデルの安定性・近似精度は，今回の実験で測定する対象です．

checkpoint より後の未保存更新は再開時に再計算します．最初の atomic checkpoint より前に
部分ファイルだけが残った場合は，既存 trainer の整合性エラーを維持します．
自動削除や条件変更による回復は実装していません．

通常の実行手順と結果の読み方は，
[ARCHITECTURE_SWEEP.md](../docs/ARCHITECTURE_SWEEP.md)を参照してください．
